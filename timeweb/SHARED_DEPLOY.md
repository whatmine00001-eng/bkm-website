# БКМ — переезд на Timeweb (обычный виртуальный хостинг)

**10 ноября 2026.** Владелец БКМ решил **перенести основную площадку с Beget на Timeweb**. Cloudflare остаётся временным сайтом до успешного переключения. Работа по GitHub продолжается.

## Конкретный аккаунт, подтверждённый в интерфейсе
- Открыт раздел Timeweb «Сайты», есть **«Основной сайт»** на техническом домене `cn705088.tw1.ru`.
- PHP 8.2 уже выбран.
- Пробный период: интерфейс показывает 10 дней; баланс 0 ₽. Финансовые обязательства без явного согласия владельца не создаём.
- Исходный код: GitHub `whatmine00001-eng/bkm-website`, ветка `timeweb/shared-v1`.

## Готовый ZIP и проверка
Workflow GitHub: https://github.com/whatmine00001-eng/bkm-website/actions/workflows/bkm-timeweb-shared.yml

Он генерирует `BKM-Timeweb-ready.zip` с публичными файлами:
- `index.html`, услуги, новости, CSS/JS, оригинальные логотипы;
- `privacy.html`, `consent.html`;
- `api/lead.php`, `api/form-config.php`;
- `assets/form-setup.js` — самостоятельная форма для РФ без Cloudflare CAPTCHA.

Никаких секретов и реального вебхука в ZIP нет. Для тестового домена временно выставлены `robots.txt Disallow` и `noindex`; после доменного переключения требуется пересобрать без этой блокировки.

## Шаг 1. Разместить публичный сайт на Timeweb

1. В панели Timeweb открыть «Файловый менеджер».
2. Перейти в папку **основного сайта** `public_html`, сохранить/переименовать стартовую заглушку, если она есть.
3. Загрузить готовый `BKM-Timeweb-ready.zip` и **распаковать содержимое прямо в `public_html`**. Файл `index.html` должен находиться в корне `public_html`, не в дополнительной папке `BKM-Timeweb-ready`.
4. Проверить открытие `http://cn705088.tw1.ru/` (только общедоступные страницы, не отправлять форму по HTTP).
5. Настроить бесплатный SSL на технический домен, если доступен. В Bitrix24 контактные данные по HTTP не отправлять.

## Шаг 2. Приватная интеграция Bitrix24

В файловом менеджере создать папку `.bkm_private` **рядом с `public_html`**, не внутри неё, затем `config.php`.

Файл должен возвращать PHP-массив аналогично примеру `timeweb/shared-config.example.php` в исходниках. В нём установить:
- `enabled => false` до HTTPS и тестов;
- `privacy_approved => true`;
- `assigned_by_id => 7`;
- `rate_salt` — случайное значение минимум 32 символа;
- `bitrix_webhook_url` — приватный URL ранее созданного входящего вебхука CRM Bitrix24.

Пароли и токены **не показывать в чате и не коммитить в GitHub**.
После настройки и HTTPS сменить `enabled` на `true`, проверить `GET https://<hostname>/api/form-config.php` — ожидается `ready:true` и публичный талон с коротким сроком действия. Не публиковать сам талон в переписке.

Форма отправляется на `/api/lead.php`; ограничения на телефон, email, имя и тип услуги проверяются на сервере. Назначение нового лида — ID 7.

## Шаг 3. Проверка и переключение DNS

1. Проверить мобильную версию, фото, шрифты, ссылки, услуги, политику, согласие.
2. Создать **одну** помеченную тестовую заявку без реальных персональных данных и подтвердить её в Bitrix24 (ID 7), не повторяя при таймауте.
3. Добавить домен `24bkm.com` к этому сайту на Timeweb и выпустить SSL для боевого домена.
4. На GoDaddy либо у фактического DNS-провайдера поменять **только веб A/AAAA/CNAME записи** на подтверждённый IP Timeweb, не NS, не MX/SPF/DKIM/DMARC, не Exchange/OWA, не `bitrix.24bkm.com`.
5. После переключения отключить технические `noindex` и `Disallow` в сборке.
6. Принять решение об обновлении текста политики: в ней фактически упомянут Beget; после переноса требуется указать реальный хостинг и схему обработки, не меняя юридические пункты без утверждения.

## Защита от спама

В Timeweb shared используется локальный PHP HMAC-талон, выдаваемый зашифрованным серверным ключом, возраст от 3 секунд до часа, honeypot и лимит 5 запросов/час на IP. Поэтому **публикация не зависит от внешнего Cloudflare Turnstile**, что важно для РФ.
