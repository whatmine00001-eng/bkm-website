# БКМ — запуск на Timeweb Cloud App Platform

**Состояние 10 ноября 2026:** исходники и Docker-сборка подготовлены и проверены в GitHub. Никакого приложения на Timeweb Cloud из этого чата не заказано и не опубликовано. DNS GoDaddy, корпоративная почта и Cloudflare не менялись.

## Выбранная архитектура

- **Timeweb Cloud App Platform** — целевой хостинг вместо Beget.
- GitHub: `whatmine00001-eng/bkm-website`; ветка `timeweb/app-platform-v1`.
- `Dockerfile` в корне репозитория собирает сайт в PHP 8.2 + Apache.
- Фирменный HTML, новости, картинки, документы, SEO — общие для Cloudflare и Timeweb.
- `api/lead.php` создаёт лиды в коробочном `https://bitrix.24bkm.com`, назначая владельца **ID 7**.
- Для России форма использует **собственную PHP-защиту**: секретный HMAC-подписанный талон, задержка минимум 3 секунды, honeypot, ограничение 5 заявок/час на идентификатор IP. Не требует Cloudflare Turnstile и его заблокированных скриптов.
- База лидов не размещается на Timeweb: лид отправляется в Bitrix24. В App Platform локальные файлы (например, лимитер) стираются при новом деплое.

## 1. Создание в панели Timeweb Cloud

В уже открытом у владельца проекте «Общий проект»:

1. Перейти в **App Platform → Задеплоить из репозитория**.
2. Подключить GitHub и разрешить доступ только к репозиторию `whatmine00001-eng/bkm-website`.
3. Выбрать **ветку `timeweb/app-platform-v1`**, включить автоматический деплой новых коммитов.
4. **Фреймворк: Dockerfile** (файл находится в корне; директорию проекта не менять).
5. **Регион: Россия** (предпочтительно Москва) с проверкой фактической локации приложения.
6. Выбрать доступную минимальную конфигурацию и внимательно проверить стоимость. Сервис может быть платным; не запускать счёт/услугу без явного решения владельца.
7. Имя приложения: `bkm-website`; проект «Общий проект».
8. После создания найти бесплатный технический домен в Dashboard. **Не изменять 24bkm.com и DNS** до завершения проверки.

Официально: https://timeweb.cloud/docs/apps/deploying-with-dockerfile

## 2. Секреты и параметры App Platform

Добавляются через Timeweb Cloud → App Platform → приложение → Настройки → переменные. **Никогда не помещать значения секретов в GitHub, переписку, код или публичный Dockerfile.**

| Переменная | Значение | Тип |
|---|---|---|
| `BKM_CRM_ENABLED` | `false` до проверки готовности, потом `true` | Публичная настройка |
| `BKM_ALLOWED_HOSTS` | `24bkm.com,www.24bkm.com,ТЕХНИЧЕСКИЙ_ДОМЕН_TIMEWEB` | Публичная настройка |
| `BKM_BITRIX_WEBHOOK_URL` | полный **действующий входящий webhook** коробочного Bitrix24, `https://bitrix.24bkm.com/rest/ID/TOKEN/` | СЕКРЕТ |
| `BKM_RATE_SALT` | собственная случайная строка длиной не менее 32 символов, лучше 64 | СЕКРЕТ |

`BKM_HOSTING_TARGET=timeweb` уже зафиксирован в Dockerfile и не должен переопределяться.

**Важно про webhook:** он уже хранится в Cloudflare как `BKM_BITRIX_WEBHOOK_URL`. Значение не копируется из GitHub. Его можно безопасно перенести внутри админок либо заново создать в Bitrix24 с правами CRM, НЕ сообщая секрет в чат. Старый webhook не отзывать до успешного теста.

### Что увидит пользователь до готовности секретов

Сайт открывается, ссылки и контент работают. Отправка формы выключена до правильной настройки переменных; при недоступности посетителю показываются корпоративные email и телефон.

### Верификация против спама

`/api/form-config.php` создаёт короткоживущий публичный HMAC-талон. Его подпись проверяется на сервере в `api/lead.php`. Талон ограничен текущим доменом, действует не более часа и не принимается в первые 3 секунды. Пользователю не нужно проходить CAPTCHA. Реальный секрет HMAC никогда не отправляется клиенту.

## 3. Проверка на техническом домене

1. Включить `BKM_ALLOWED_HOSTS` с **точным техническим hostname** (без `https://`, путей или слеша).
2. Для просмотра до настройки Bitrix/секретов оставить `BKM_CRM_ENABLED=false`.
3. После настройки секретов включить `BKM_CRM_ENABLED=true` и сделать Redeploy.
4. Убедиться, что `GET /api/form-config.php` отвечает `ready:true` с публичным `form_token`. Не публиковать этот одноразовый токен в отчёте.
5. Убедиться, что нет ошибок PHP, страницы услуг работают, документы и форма отображаются с мобильного.
6. Отправить **только одну вымышленную тестовую заявку**. Проверить в Bitrix24, что она создана, у ответственного ID 7, без дублей. При 502 или таймауте **не отправлять повторно**, сначала искать лид в CRM.
7. Проверить доступность из РФ через обычного оператора связи и из Казахстана.

## 4. Переключение домена

Когда технический домен полностью проверен:

1. В App Platform → Настройки → Домены добавить `24bkm.com` и `www.24bkm.com` как внешние домены (GoDaddy остаётся регистратором).
2. У GoDaddy или текущего DNS-провайдера обновить **только веб-записи A/AAAA/CNAME**, указав фактические значения Timeweb. Не менять NS, MX, SPF, DKIM, DMARC, записи Exchange, OWA, `bitrix.24bkm.com`.
3. Проверить автоматический Let's Encrypt и HTTPS, затем `/api/form-config.php`, форму, мобильную версию, главную и новости.
4. После успешной проверки можно сохранить Cloudflare Pages как резервный тестовый адрес, без привязки к основному домену.

В панели Timeweb Cloud App Platform собственные и технические домены сопровождаются SSL; детали https://timeweb.cloud/docs/apps/domain .

## 5. Хранение и правовые тексты

Утверждённая политика БКМ пока указывает Beget как хостинг. При фактическом запуске на Timeweb **это описание необходимо привести в соответствие с действительной инфраструктурой**; нельзя молча выдавать старые фактические сведения за актуальные. Контакты, сроки и другие утверждённые пункты не менять без отдельного указания.
