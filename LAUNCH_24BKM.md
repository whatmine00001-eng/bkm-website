# План безопасного запуска нового сайта на 24bkm.com

Версия: 22.10.2026. **Запуск пока не разрешён; не менять DNS до выполнения проверок.**

## Инфраструктура
- Регистратор и текущий DNS: GoDaddy (подтвердить авторитетные NS перед изменением).
- Рабочая ветка нового сайта в GitHub: `design/bkm-modern-v1`.
- Основной сайт Beget: `/home/h/help24pw/24bkm.com/public_html`.
- Тестовый сайт Beget: `/home/h/help24pw/test.24bkm.com/public_html`.
- Отдельное тестовое размещение: `/home/h/help24pw/test.24bkm.com/public_html/bkm-preview/`.
- IP, предложенный Beget для домена: `45.130.41.212`. Проверить актуальность непосредственно перед запуском.
- Текущий 24bkm.com и его SSL работают на старой инфраструктуре. Коробочная CRM: `bitrix.24bkm.com`.
- SSL для нового основного сайта нужно обеспечить **отдельно на Beget**; сертификат GoDaddy не переносится автоматически.

## Стоп-факторы, обнаруженные в GitHub
- `index.html` и статьи содержат `<meta name="robots" content="noindex,nofollow">` (для рабочей версии снять, для превью сохранить).
- `assets/site-config.js`: `formsEnabled: false` и `analyticsEnabled: false`.
- `privacy.html` — черновик, не утверждённая политика.
- Серверный Bitrix webhook в GitHub отсутствует по замыслу; закрытая конфигурация на Beget требует настройки, новый секрет после демонстрации старого токена, проверки работы `crm.lead.add`.
- Есть неподтверждённые публичные утверждения о годе работы и составе услуг; проверить перед запуском.
- Нужно составить карту редиректов со старых URL, в том числе страницы `/contact`.

## Предпусковые действия
1. Получить снимок всех DNS-записей GoDaddy: A `@`, AAAA `@` (если есть), CNAME/A `www`, A/CNAME `bitrix`, mail / autodiscover / MX / SPF / DKIM / DMARC / CAA. Проверить, что важные сервисы не CNAME к `@` и не зависят от IP старого сайта. **NS не менять**.
2. Зафиксировать исходный A-адрес `@` и время TTL для отката. Сохранить все активные старые URL, проверить посещаемые и важные страницы.
3. Собрать новый сайт в тестовой папке Beget (GitHub Actions) и проверить главное меню, услуги, новости, ссылки, изображения, мобильную версию и отсутствие ошибок PHP/JS.
4. Установить бесплатный SSL на `test.24bkm.com` (если нужен тест онлайн-формы), опубликовать и утвердить реальную политику персональных данных и юридические реквизиты.
5. Настроить закрытый webhook в `/home/h/help24pw/.bkm_private/config.php`. Не публиковать его в GitHub. Проверить, работают ли лиды в коробочном Bitrix24. Отправить одну тестовую заявку на своём тестовом контакте по HTTPS; убедиться, что она появилась именно в нужной воронке или таблице лидов. Проверить защиту от спама и ошибку CRM.
6. Создать Яндекс Метрику для `24bkm.com`, задать номер счётчика, 3 цели, проверить события. Собрать `sitemap.xml`, `robots.txt`, корректные canonical и ссылки на публичный адрес. Не оставлять robots noindex на публичном сайте.
7. Согласовать способ публикации на продакшен: отдельный ручной workflow с подтверждением, резервная копия файлов `24bkm.com/public_html`, копирование в эту папку **без необоснованного удаления**, проверка. Служебный Beget `index.php` нужно после проверки убрать из корня (в бэкап вне `public_html`), иначе он может перекрывать `index.html`.

## Переключение DNS только после готовности
1. GoDaddy → DNS → A-запись **Name: @**, **Value: 45.130.41.212** (адрес ещё раз сверить в Beget перед изменением), TTL 600–3600. **Изменить текущую запись A, не создавать дубли**.
2. Для `www` проверить текущий CNAME: если он указывает на `@`, обычно отдельной правки не требуется; если `www` имеет свою A-запись или CNAME на старый хостинг — перенаправить на новый Beget согласно его инструкциям.
3. Проверить AAAA для `@` и `www` и удалить/изменить старые IPv6-записи только если они указывают на старый сайт и нет поддержки IPv6 на новом; остальные записи не менять. Важно: записи `bitrix`, `mail`, `MX`, `TXT` и любые записи, зависящие от `@`, должны продолжать вести на нужные сервисы.
4. Когда новый IP виден у авторитетных DNS и Beget, выпустить Let's Encrypt для **24bkm.com и www.24bkm.com** в Beget. Не считать существующий GoDaddy SSL действующим на новом сервере. В период переключения возможна краткая недоступность HTTPS.
5. Проверить ответы 200 на HTTPS без `/bkm-preview/`, карту 301 для старых URL, HTTPS-редирект, работу CRM и Метрики, отправку заявки, доступность файлов и логи.
6. Сохранить старый хостинг и точные старые DNS-значения на время наблюдения. При необходимости откатить A/CNAME, с учётом TTL.

## Условия успеха
- `https://24bkm.com/` открывает новый сайт с корректным сертификатом.
- `https://www.24bkm.com/` корректно перенаправляет на основную версию.
- `https://bitrix.24bkm.com/` и рабочая почта не изменились.
- Контактные формы дают подтверждение после фактического создания записи в CRM.
- Поисковые роботы не блокируются noindex, `sitemap.xml` корректен, старые популярные URL возвращают релевантные 301.
- Метрика получает посещения и цели, есть проверенные телефоны и адреса.
- Доступен откат.

## Выпуск главного сайта: ручной сценарий (подготовлен 22.10.2026)
Файл GitHub Actions в `main`: `.github/workflows/prepare-beget-production.yml`.

**Режим `prepare`**: собирает версию в `_production_release`, проверяет страницы и копирует файлы в **закрытый** каталог `/home/h/help24pw/.bkm_releases/24bkm-<commit>`. Публичная папка и DNS не меняются.

**Режим `publish`**: только при ручном выборе и точном вводе `RELEASE_24BKM`; создаёт резервную копию `/home/h/help24pw/24bkm.com/public_html` в `/home/h/help24pw/.bkm_backups/`, перемещает стандартный `index.php` в резервную папку и выкладывает проверенную сборку в корень сайта. GitHub Actions не меняет GoDaddy DNS, NS, корпоративную почту или Bitrix24.

Перед изменением A-записей убедиться, что шаг `publish` завершился зелёным статусом, а HTTP-страница на Beget открывается с заданным Host:
```powershell
curl.exe -I --resolve 24bkm.com:80:45.130.41.212 http://24bkm.com/index.html
curl.exe --resolve 24bkm.com:80:45.130.41.212 http://24bkm.com/index.html
```
Первая команда должна показать `HTTP/1.1 200`, во второй должен присутствовать новый слоган «Для нас нет невозможного». Этот тест проверяет **только HTTP**, не готовность SSL.

После успешной проверки меняются только A-записи `@` и `www` на `45.130.41.212` (сверить актуальный адрес Beget) с сохранением MX/TXT, `bitrix`, `ai` и `test`. После распространения DNS выпустить/проверить SSL на Beget и отсутствие ошибок HTTPS, а затем тестировать функциональность. Не менять DNS, пока успешность публикации и проверки не подтверждена.

Текущая публикационная версия временно отключает автоматическую форму заявок (оставлены `mailto:` и `tel:`), не выкладывает неопубликованный проект политики обработки персональных данных и не активирует Метрику до согласования. Это необходимо отличать от полноценного CRM-запуска.
