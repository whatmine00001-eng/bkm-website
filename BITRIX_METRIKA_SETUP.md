# Интеграция БКМ ↔ коробочный Bitrix24 + Яндекс Метрика

Статус на 22 октября 2026: **код подготовлен, включение приёма личных данных и аналитики сознательно заблокировано до безопасной настройки**.

## Архитектура
- `index.html`: форма коммерческого запроса, согласие, UTM и сообщение о результате.
- `assets/lead-form.js`: отправка из браузера при HTTPS и `formsEnabled: true`. В противном случае — понятный режим подготовки письма в почтовой программе.
- `api/lead.php`: серверный PHP-приёмник на Beget, HTTPS-only, разрешает запросы с того же хоста, проверяет данные, применяет honeypot и лимит 5 попыток на IP-час, отправляет данные в `crm.lead.add.json` вашего коробочного Bitrix24.
- `assets/site-config.js`: только публичные переключатели, без паролей и webhook.
- `assets/analytics.js`: Яндекс Метрика и цели `bkm_lead_success`, `bkm_phone_click`, `bkm_email_click`. Загружает счётчик, только когда включён и используется HTTPS.
- `privacy.html`: явно помеченный **черновик** документа. Перед приёмом заявок заменить настоящей политикой утверждённого оператора персональных данных.

### Почему пока всё отключено
Технический тестовый адрес `http://help24pw.beget.tech/bkm-preview/` работает по **HTTP, не по HTTPS**. Не собирайте на нём контактные данные автоматически. Не включайте `formsEnabled` или серверный флаг до настройки защищённого домена и актуальных юридических документов.

## 1. Безопасная настройка Beget (вручную в личном терминале, не в чате)
Создайте закрытую директорию **вне** `public_html`:

```bash
mkdir -p /home/h/help24pw/.bkm_private
chmod 700 /home/h/help24pw/.bkm_private
nano /home/h/help24pw/.bkm_private/config.php
```

Вставьте **пример конфигурации**, заменив значения на свои. Не сохраняйте секрет в GitHub, файлах сайта или переписке:

```php
<?php
return [
    'enabled' => false,
    'privacy_approved' => false,
    'bitrix_webhook_url' => 'https://bitrix.24bkm.com/rest/USER_ID/NEW_SECRET_TOKEN/',
    'rate_salt' => 'REPLACE_WITH_RANDOM_LONG_SECRET'
];
```

После сохранения:

```bash
chmod 600 /home/h/help24pw/.bkm_private/config.php
```

Этот файл **никогда** не должен попадать в `public_html`, `/bkm-preview/` или коммиты GitHub. Если ранее вебхук отображался на скриншоте, обязательно перегенерируйте его. Дайте вебхуку минимальные права CRM; ещё лучше — отдельный технический пользователь.

## 2. Проверка Bitrix24
1. Убедитесь, что в вашей коробке доступны **лиды**; скрипт использует `crm.lead.add`, не создание сделки в Kanban.
2. Убедитесь, что входящий webhook имеет право CRM и технический пользователь может создавать лиды.
3. Если отдел работает **без лидов**, потребуется альтернативный сценарий: контакт + сделка в нужной воронке. Не включайте текущий обработчик, пока не согласована структура CRM.
4. После подготовки отдельного HTTPS-домена и политики разрешите `'enabled' => true` и `'privacy_approved' => true`.
5. Измените `assets/site-config.js`: `formsEnabled: true`. Проверьте отправку **своего тестового контакта** и появление записи в Bitrix24. Не используйте личные данные посторонних для тестирования.
6. Только после подтверждения результата запустите публикацию на основной домен.

## 3. Яндекс Метрика
1. Войдите в официальный интерфейс: https://metrika.yandex.ru/
2. Создайте счётчик для будущего HTTPS-домена `24bkm.com` и сохраните **числовой номер счётчика** (это публичный идентификатор, не пароль).
3. Создайте три цели с типом «JavaScript-событие» и идентификаторами:
   - `bkm_lead_success` — сервер подтвердил создание лида;
   - `bkm_phone_click` — нажатие на `tel:` (не фактический звонок);
   - `bkm_email_click` — нажатие на `mailto:` (не отправка письма).
4. После утверждения политики и настройки HTTPS укажите `metrikaId: 12345678` (**настоящий номер**) и `analyticsEnabled: true` в `assets/site-config.js`.
5. В реальном интерфейсе Метрики проверьте активность счётчика и срабатывание целей. Пока выключено, никакой счётчик на сайте не работает.

Яндекс Метрика: https://yandex.ru/support/metrica/ru/objects/reachgoal

## 4. Развёртывание GitHub → Beget
Ветка разработки: `design/bkm-modern-v1`. Скрипт предварительного развёртывания: `.github/workflows/publish-beget-preview.yml` в `main`.

- Код PHP и JS загружается только из GitHub. Закрытый файл `/home/h/help24pw/.bkm_private/config.php` не трогается.
- Предварительные версии на HTTP предназначены для просмотра, не для сбора клиентских данных.
- До публичного запуска должны быть готовы политика, HTTPS, контакты и юридические реквизиты.
- После запуска проверить статусы 200 и 404, логи PHP, формы, цели Метрики и оформление лидов в Bitrix24.
- При ошибке CRM интерфейс не сообщает «заявка отправлена». Посетителю показывается предложение позвонить или написать.
