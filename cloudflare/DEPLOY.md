# БКМ · Cloudflare Pages: перенос с Beget без изменения домена

**Статус на 06.11.2026:** код готов в ветке `cloudflare/pages-v1`; безопасная сборка и синтетические тесты Bitrix24 проходят. **Проект в аккаунте Cloudflare НЕ создан; DNS НЕ переключён; данные клиентов НЕ принимаются.**

## 1. Что сделано
- Источник: `whatmine00001-eng/bkm-website`, ветка `cloudflare/pages-v1`, отдельно от `main` и `design/bkm-modern-v1`.
- Cloudflare Pages собирает исходный статический сайт в `dist/` из `cloudflare/build-pages.py`.
- В `dist/` нет PHP, webhook URL, SSH-ключей, серверной конфигурации и обработчика Beget.
- Загруженные пользователем DOCX преобразованы в `cloudflare/legal/privacy.html` и `cloudflare/legal/consent.html`. Смысл юридических пунктов не редактировался; страницы **помечены как требующие согласования** и исключены из индексации.
- Контактная форма на preview отключена; связь — через корпоративную почту и телефон.
- `functions/api/lead.js` — Cloudflare Pages Function для безопасной передачи лида в коробочный Bitrix24 при подтверждённом юридическом допуске, наличии Turnstile и закрытых секретов. Ответственный ID 7. Без полномочий/секретов endpoint возвращает 503.
- `cloudflare/test-lead.mjs` — автономные проверки без реальных обращений в Bitrix24.

## 2. Один шаг владельца: связать Cloudflare с GitHub
1. Зайти в **https://dash.cloudflare.com/** под аккаунтом компании БКМ.
2. **Workers & Pages → Create application → Pages → Connect to Git**.
3. Авторизовать GitHub только для `whatmine00001-eng/bkm-website`.
4. Выбрать этот репозиторий и установить **Production branch**: `cloudflare/pages-v1`.
5. Framework preset: **None**; **Build command**: `python3 cloudflare/build-pages.py`; **Build output directory**: `dist`; root directory: пусто / repository root.
6. Добавить обычную переменную сборки `BKM_PAGES_MODE=review_only` (значение по умолчанию и без неё).
7. Запустить Deploy. Появится `<project>.pages.dev` с безопасной демоверсией; новые коммиты в выбранной ветке будут публиковаться автоматически.
8. Прислать `*.pages.dev` ссылку для визуальной/функциональной проверки. До полной проверки **не добавлять custom domain**.

Официальные инструкции: https://developers.cloudflare.com/pages/get-started/git-integration/ .

## 3. Почему форма пока не включена
Исходные документы противоречат друг другу:
- `политика обработки данных(1).docx`: первичный запрос без маркетингового профилирования; внешняя аналитика отдельно; ориентир до 90 дней активной обработки; размещение через Beget; первичная передача иностранным получателям не предусмотрена.
- `согласие на обработку.docx`: включает маркетинг и интернет-статистику; действие согласия 30 дней.
- Cloudflare Pages / Pages Functions исполняются на инфраструктуре Cloudflare, что влияет на реальное место обработки технических и контактных данных. Нельзя автоматически считать это эквивалентом российского сервера Beget.

**До получения окончательно согласованных редакций и решения о размещении персональных данных:** используем только preview с `BKM_PAGES_MODE=review_only`. Никакой настоящий лид не создаётся. Технический маркер `approved` — не замена юридическому решению. В загруженных документах не следует молча менять цели, сроки или обработчиков.

## 4. Как будет работать Bitrix24 после согласования
Запрос формы HTTPS → Pages Function `POST /api/lead` → обязательная проверка Turnstile → закрытый серверный вызов `crm.lead.add.json` → лид в коробочной Bitrix24 с `ASSIGNED_BY_ID=7`.

Подготовленный обработчик не читает клиентские лиды, не записывает ФИО или телефоны в Cloudflare KV/D1, не печатает webhook в логи и **не повторяет** отправку при неопределённом результате.

### Предпосылки перед выпуском
- Утвердить согласованные тексты политики и согласия с учётом реального маршрута обработки, трансграничных условий и обработки Cloudflare.
- Утвердить корректное место первичного сбора/хранения данных граждан РФ по применимому закону. При необходимости разместить приёмник лидов на контролируемом сервере в РФ и не пропускать содержание заявок через зарубежный edge.
- Обновить оба HTML-документа, явно снять `bkm-policy-review=pending`, получить от владельца разрешение на выпуск и выставить `bkm-policy-status=approved`.
- Создать Cloudflare Turnstile для основного домена и проверить ограничения, уведомления и доступы.
- В коробочной Bitrix24 создать/перевыпустить **входящий webhook с минимальными правами CRM**. После инцидента Beget старые ключи желательно отозвать. Не присылать webhook в чат и не коммитить в GitHub.

### Переменные для будущей рабочей версии
**Build** (не секретные):
- `BKM_PAGES_MODE=active` — только после согласования документов.
- `BKM_TURNSTILE_SITE_KEY=<public site key>` — публичный ключ виджета.

**Runtime** (Cloudflare Pages project → Settings → Variables and Secrets):
- `BKM_CRM_ENABLED=true` и `BKM_LEGAL_APPROVED=true` — серверные предохранители, включить только после проверки.
- `BKM_CONSENT_VERSION=<approved document ID>`.
- `BKM_BITRIX_WEBHOOK_URL` — **Encrypted Secret**, формат `https://bitrix.24bkm.com/rest/<id>/<token>/`.
- `BKM_TURNSTILE_SECRET` — **Encrypted Secret**.

В полном выпуске отправка идёт на `/api/lead`, не `/api/lead.php`; Cloudflare Pages **не исполняет PHP**.

## 5. Домен и корпоративная почта
- Пока preview не готов — **никаких изменений GoDaddy, NS, A, CNAME, MX, SPF, DKIM, DMARC, Exchange, Bitrix24**.
- После проверки Pages + backend подключаем основной `24bkm.com` к Pages и выполняем проверку HTTPS, www, мобильной версии, контактной формы.
- Прежний хостинг Beget не удалять до успешного переноса и резервной копии.
- Продумать защиту от региональных ограничений доступности Cloudflare, потому что БКМ работает с клиентами из РФ и других стран.

## 6. Программа проверки перед запуском лидов
1. Сборка `python3 cloudflare/build-pages.py` — GitHub Actions зелёный.
2. `node --test cloudflare/test-lead.mjs` — только фейковые данные.
3. Проверка страниц, логотипа, контактов и оформления на телефоне и ПК.
4. Проверка закрытых настроек сервера / Turnstile / HTTPS / статуса согласования.
5. Только затем один помеченный тестовый лид; проверить `SOURCE_ID=WEB`, `ASSIGNED_BY_ID=7`, создание без дублей.
6. Мониторинг заявок, уведомления менеджеру, логика обработки отказа.

**Всё, что в этом документе после подключения Cloudflare и юридического согласования, является дальнейшими действиями, а не уже выполненными операциями.**
