# БКМ — Cloudflare Pages + Bitrix24

**Состояние на 6 ноября 2026:** техническая интеграция сайта с Bitrix24 реализована в ветке `cloudflare/pages-v1` и проходит GitHub Actions. Пользователь **явно подтвердил утверждение** двух загруженных юридических документов. Публикация в аккаунте Cloudflare и живой лид через новую площадку ещё не выполнены: Cloudflare не подключён к этому чату/репозиторию, а секреты Cloudflare здесь недоступны.

## Что уже готово

- Сайт на базе `design/bkm-modern-v1`, в том числе фирменный дизайн, страницы услуг, новости, контакты.
- Страницы `/privacy.html` и `/consent.html` на основе утверждённых пользователем DOCX без самовольного изменения их текста; технический метатег `bkm-policy-status=approved` и версия согласия.
- Сборка `cloudflare/build-pages.py` с двумя режимами:
  - `review_only`: форма недоступна, сайт можно проверять без передачи контактных данных;
  - `active`: полноценная форма отправляет JSON на `/api/lead`. Для сборки необходим публичный ключ Turnstile.
- Обработчик `functions/api/lead.js` — Cloudflare Pages Function. Проверяет HTTPS, точный Host и Origin, параметры формы, согласие, Turnstile и затем отправляет лид через `crm.lead.add.json` коробочной Bitrix24.
- Поля: название лида, ФИО, телефон, компания, email, услуга, пункты отправления/назначения, груз, комментарий, UTM-метки; источник `WEB`, ответственный **ID 7 (Кирилл)**.
- Вебхук Bitrix24 нигде не публикуется: используется только runtime-зашифрованный секрет Cloudflare.
- Лид подтверждается только при наличии положительного ответа API Bitrix24; при ошибке/таймауте автоматически не повторяется.
- `cloudflare/test-lead.mjs`: тесты, включая сквозную имитацию браузерного POST → Pages Function → Bitrix24 на синтетических данных, без настоящего доступа в CRM.

## Подключить Cloudflare Pages (владелец аккаунта)

В панели https://dash.cloudflare.com/:

1. **Workers & Pages → Create application → Pages → Connect to Git**.
2. Авторизовать GitHub, выбрать только репозиторий `whatmine00001-eng/bkm-website`.
3. Production branch: `cloudflare/pages-v1`.
4. Framework preset: **None**; build command: `python3 cloudflare/build-pages.py`; output directory: `dist`; root directory — корень репозитория.
5. Для первого просмотра можно сохранить `BKM_PAGES_MODE=review_only`. Для рабочей формы установить **Build environment variables**:
   - `BKM_PAGES_MODE=active`
   - `BKM_TURNSTILE_SITE_KEY=<публичный site key созданного Turnstile widget>`
6. Создать widget Turnstile для реального домена `24bkm.com`, `www.24bkm.com`; для тестирования на `*.pages.dev` добавить точный домен сайта в настройки Turnstile.
7. В проекте Pages → **Settings → Variables and Secrets** добавить **Runtime**:
   - `BKM_CRM_ENABLED=true` (обычная переменная — включение после задания остальных значений);
   - `BKM_CONSENT_VERSION=bkm-consent-uploaded-2026-11-06-v1` (обычная переменная);
   - `BKM_BITRIX_WEBHOOK_URL` = действующий входящий webhook Bitrix24 `https://bitrix.24bkm.com/rest/ID/SECRET/` (**encrypted secret**);
   - `BKM_TURNSTILE_SECRET` = секретный ключ Turnstile (**encrypted secret**).
   - Для тестирования формы на `*.pages.dev` также `BKM_PREVIEW_HOST=<точный_проект>.pages.dev` (обычная переменная). В отсутствие переменной обработчик принимает только `24bkm.com` и `www.24bkm.com`.
8. Запустить **Save and Deploy**. Cloudflare получит репозиторий напрямую из GitHub. После публикации прислать полученную ссылку вида `https://<проект>.pages.dev`, чтобы проверить, что Pages Function действительно задеплоен. Фактическая отправка в Bitrix24 должна быть подтверждена отдельным служебным лидом, не одними локальными тестами.

**Важно:** на `pages.dev` для реального POST нужны одновременно `BKM_PREVIEW_HOST` и домен в Turnstile. Секретные URL и ключи не присылать в переписку.

## Проверка перед сменой DNS 24bkm.com

- Открывается `index.html`, работает адаптивное меню, стили, новости, обе юридические страницы.
- `/api/lead` возвращает 405 на GET и JSON на POST.
- 1 явно помеченная синтетическая заявка создаётся как **лид** с `ASSIGNED_BY_ID=7` и `SOURCE_ID=WEB`; проверяется ID и отсутствие дубля. Пробные настоящие контактные данные не использовать.
- Проверяется ответ при некорректном телефоне, выключенной галочке, ошибке Turnstile и недоступной CRM.
- После подтверждения можно подключать custom domain и обновлять только необходимые **веб-записи** домена. **Не изменять MX, SPF, DKIM, DMARC, Exchange и настройки bitrix.24bkm.com.**

В предоставленной политике Beget назван в числе размещающих сайт подрядчиков, а в согласии указаны дополнительные цели маркетинга и статистики. Пользователь подтвердил эти документы как согласованные; **текст мы не переписывали**. При фактическом переносе обработки запросов на Cloudflare оператору следует убедиться, что опубликованный перечень обработчиков, трансграничные аспекты и размещение российских баз отражают реальную схему. Это отдельная проверка фактов размещения, **а не запрос повторного согласования уже переданных редакций**.
