# БКМ: подключение заявок 24bkm.com к **лидам** коробочной Bitrix24

Статус: **код интеграции и проверочный механизм готовы; реальная отправка ещё НЕ активирована**. Перед включением нужны реальные настройки CRM, одобренная политика персональных данных и тестовая заявка. Дизайн сайта не изменяется.

## 1. Что уже работает в коде

- Форма `index.html#contact` собирает имя, телефон, компанию, email, услугу, маршрут, груз и описание задачи.
- `assets/lead-form.js` отправляет данные по HTTPS методом POST на **свой** `/api/lead.php`. UTM-метки захватываются только из допустимых `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`.
- `api/lead.php` на Beget валидирует входные данные, согласие и источник, фильтрует ботов, ограничивает частоту запросов и сервер-сервер передаёт заявку по REST в `crm.lead.add.json` на **bitrix.24bkm.com**.
- Поля Bitrix24: `TITLE`, `NAME`, `COMPANY_TITLE`, `PHONE`, `EMAIL`, `SOURCE_ID=WEB`, `SOURCE_DESCRIPTION`, `STATUS_ID=NEW`, `COMMENTS`, `UTM_*`. В `COMMENTS` записываются маршрут, наименование груза, услуга и описание задачи.
- При необходимости `ASSIGNED_BY_ID` и `STATUS_ID` задаются в закрытой конфигурации БКМ.
- Успех пользователю показывается **только после** успешного ответа API Bitrix24; при ошибке предлагается телефон или email.
- Пока CRM не активирована, **основной сайт остаётся в безопасном режиме email/телефон**.

Документация Bitrix24: https://apidocs.bitrix24.ru/api-reference/crm/leads/crm-lead-add.html

## 2. Действия администратора Bitrix24 (без передачи секрета в чат)

Откройте https://bitrix.24bkm.com/ под администратором CRM:

1. Убедитесь, что ваш режим CRM поддерживает **лиды** и у технического пользователя есть право создавать лиды (а не только сделки).
2. Откройте раздел **Разработчикам → Вебхуки → Входящий вебхук** (названия пунктов могут различаться в вашей коробочной версии).
3. Создайте вебхук для отдельного технического пользователя с **минимально необходимым доступом CRM**. При возможности ограничьте IP источника адресами хостинга.
4. Для команд в терминале Beget используйте **php8.2**, а не **php**: встроенный **php** может быть устаревшей версией CLI.\n\n4. Скопируйте секретный URL вида `https://bitrix.24bkm.com/rest/ID/SECRET/`. Это **пример структуры**, а не адрес для копирования.
5. **Никогда не присылайте реальный вебхук сюда и не помещайте его в GitHub**. Если ранее вебхук попадал на скриншот, обязательно перевыпустите ключ.
6. Найдите ID сотрудника, ответственного за новые лиды. При желании можно подключить Bitrix24-робота на событие создания лида, который уведомляет менеджера и ставит задачу.

Источник: https://helpdesk.bitrix24.ru/open/20886106/

## 3. Приватная конфигурация Beget

Сайт размещён в `/home/h/help24pw/24bkm.com/public_html`. Секреты должны лежать **снаружи** веб-каталога:

```bash
mkdir -p /home/h/help24pw/.bkm_private
chmod 700 /home/h/help24pw/.bkm_private
nano /home/h/help24pw/.bkm_private/config.php
```

Содержимое **примера** (подставить собственные значения только в личном терминале Beget):

```php
<?php
return [
    'enabled' => false,
    'privacy_approved' => false,
    'bitrix_webhook_url' => 'https://bitrix.24bkm.com/rest/123/REPLACE_WITH_NEW_SECRET/',
    'rate_salt' => 'REPLACE_WITH_A_UNIQUE_RANDOM_64_CHARACTER_HEX_STRING',
    'assigned_by_id' => 123,
    'lead_status_id' => 'NEW',
];
```

Создать случайный `rate_salt` можно на Beget командой:

```bash
php8.2 -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

Проверьте, что `assigned_by_id` — реальный ID менеджера в вашей Bitrix24. Поле необязательно, можно удалить строку до определения менеджера; Bitrix24 применит свою логику назначения. `lead_status_id` необязательно — по умолчанию `NEW`.

```bash
chmod 600 /home/h/help24pw/.bkm_private/config.php
```

Пока политика не утверждена и вы не готовы провести тест, оставьте `enabled=false` и `privacy_approved=false`. **Не пытайтесь включить публичную форму преждевременно**.

## 4. Политика обработки персональных данных

У сайта пока есть только **черновик** `privacy.html`. Потребуется собственная **утверждённая** публичная политика оператора персональных данных (реальные реквизиты, контактное лицо, цели и основания обработки, сроки хранения, сервисы и т. п.). Подробный технический порядок — `approved/README.md`.

После юридического согласования добавьте `approved/privacy.html` с реальным текстом и маркером:

```html
<meta name="bkm-policy-status" content="approved">
```

Наличие маркера **не** является заменой юридического согласования. Пока файла нет, CRM-сборка **завершится ошибкой**, и действующий сайт не изменится.

## 5. Проверка вебхука и выпуск сайта (GitHub Actions)

1. После утверждения политики измените в **приватном файле Beget** значения на `enabled=true`, `privacy_approved=true`, подставьте действительный URL вебхука и случайный `rate_salt`.
2. Откройте GitHub Actions: https://github.com/whatmine00001-eng/bkm-website/actions/workflows/prepare-beget-production.yml
3. Выберите ветку **main** → **Run workflow**:
   - **mode:** `prepare`
   - **crm_mode:** `on`
   - **confirmation:** оставить пустым
4. Работа проверит Python-сборку, наличие утверждённой политики, PHP-обработчик, приватную конфигурацию на Beget, SSL-соединение и доступ к методу `crm.lead.fields` в Bitrix24 **без создания тестовых лидов**. Этот этап сохраняет файлы только в приватную папку, основная страница не меняется.
5. Только после успешной проверки снова запустите workflow:
   - **mode:** `publish`
   - **crm_mode:** `on`
   - **confirmation:** `RELEASE_24BKM`
6. Публикация создаст резервную копию текущего сайта и отправит **одобренную** форму, `privacy.html`, `api/lead.php` и публичную конфигурацию с `formsEnabled: true` в `public_html`.

**Режим по умолчанию `crm_mode=off` сохраняет форму выключенной.** Публикация сайта без CRM по-прежнему безопасна и не требует вебхука.

## 6. Один реальный контрольный лид

После `publish / on`:

- Откройте https://24bkm.com/ по HTTPS с обычного телефона или компьютера.
- Заполните форму **своими** тестовыми данными; отметьте согласие; нажмите «Отправить заявку».
- Убедитесь, что посетитель видит подтверждение **после ответа сервера**, а в **CRM → Лиды** появляется запись **«Сайт БКМ — …»** с телефоном, компанией, услугой, маршрутом и метками.
- Проверьте назначение нужного менеджера, уведомление и время реакции. Сделайте второй тест с ошибочными полями (он не должен создавать лид).
- После подтверждения очистите тестовую запись по правилам компании.

Если на сайте ошибка, проверьте PHP-логи Beget, REST-права вебхука и поля статусов CRM. В ошибки посетителей не включаются секреты. **Не делитесь здесь персональными данными клиента или URL вебхука**.

## 7. Переменные и безопасность

- `BKM_CRM_RELEASE` = `off` или `on`; контролирует **публикацию**, а не секрет вебхука.
- `formsEnabled` выставляется **автоматически только в собранной утверждённой версии**. Не менять исходный `assets/site-config.js` вручную.
- `api/lead.php` принимает запросы только по HTTPS с `24bkm.com` / `www.24bkm.com`, и проверяет `Origin`/относительный `Referer`, `Content-Type`, согласие и частоту.
- Метрика пока выключена отдельно. Для неё потребуются номер счётчика и необходимые документы/согласия.
- Автоматическое создание **контакта и сделки** здесь не выполняется: пользователь выбрал первичный этап **Лиды**.

Последующие улучшения после первых заявок: антидубли, роботы для уведомления/задач, аналитика рекламных кампаний, распределение лидов между менеджерами.
